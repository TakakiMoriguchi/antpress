# antpress 画面構成

> `DECISIONS.md` / `DATA-MODEL.md` に基づく画面一覧。
> 最終更新: 2026-09-03

## 1. 全体構造

**3 階層モデル**（→ `DECISIONS.md` 1.3）に対応して URL 空間を 3 つに分ける。

```
/admin/*       プラットフォーム管理  ← admin のみ
/*             クライアント管理      ← admin と developer が共用
/client/*      コンテンツ運用        ← client（owner / staff）
```

### 重要：`/*` を admin と developer で共用する

admin 専用のクライアント管理画面は**作らない。**
admin 自身も developer レコードを持つ（→ `DECISIONS.md` 1.3）ため、
**同じ画面で自分のクライアントを管理できる。**

画面を分けると同じものを 2 つ保守することになる。
admin だけが `/admin/*` に**追加で**アクセスできる、という構造にする。

| 空間 | admin | developer | client |
| --- | --- | --- | --- |
| `/admin/*` | ✅ | ❌ | ❌ |
| `/*` | ✅ | ✅ | ❌ |
| `/client/*` | ❌ | ❌ | ✅ |

`developers` と `users` はテーブルが別なのでセッションも分離する。

## 2. プラットフォーム管理（`/admin/*`）— admin のみ

| # | 画面 | パス | 内容 |
| --- | --- | --- | --- |
| P1 | **developer 一覧** | `/admin/developers` | 全 developer。契約状態・クライアント数 |
| P2 | **developer 発行** | `/admin/developers/new` | 招待メール送付 |
| P3 | **developer 詳細** | `/admin/developers/:id` | 停止・再開、**admin 専用メモ**（契約日・年額・入金状況） |
| P4 | API ドキュメント | `/admin/api_docs` | OpenAPI（Swagger UI / Redoc） |

**収益・統計画面は作らない。** Stripe を実装しないため表示する数値がなく、
契約状況は P1 の一覧と P3 のメモで足りる（→ `DECISIONS.md` 3.10）。

**P3 の停止操作について**: `suspended` にすると、**その developer の管理画面ログインと、
配下の全クライアントの管理画面ログイン・配信 API がまとめて停止する。** 操作は 1 つ。

SSG 前提なので実際の影響は「公開中の HP が落ちる」ではなく「更新が止まる」
（→ `DECISIONS.md` 3.10）。停止は事前連絡の上で行う。

### admin は developer のクライアントのコンテンツを見られるか

**既定では見られない。**

| 見えるもの | 見えないもの |
| --- | --- |
| クライアント数・名前・プラン・稼働状態 | **記事の中身、画像、問い合わせ内容** |

他社のクライアントの記事は **developer の商売の中身**なので、既定では触れない。
サポートが必要な場合は**記録付きの代理ログイン**でのみ参照する
（誰がいつ何を見たかを残す）。

## 3. クライアント管理（`/*`）— admin / developer 共用

| # | 画面 | パス | 内容 |
| --- | --- | --- | --- |
| D1 | ログイン | `/log_in` | developer / admin 共通 |
| D2 | パスワードリセット | `/reset_password` | |
| D3 | **クライアント一覧** | `/clients` | **自分の**クライアントのみ（admin は全件） |
| D4 | クライアント新規作成 | `/clients/new` | 名前・スラッグ・プラン |
| D5 | **クライアント詳細 / 編集** | `/clients/:id` | プラン、通知先メール、**Webhook URL**、稼働状態 |
| D6 | **オーナーアカウント発行** | `/clients/:id/users` | そのクライアントのオーナーを発行・停止 |
| D7 | **API キー管理** | `/clients/:id/api_keys` | 発行・失効。**平文は発行時に一度だけ表示** |
| D8 | **Anthropic API キー設定** | `/settings/anthropic` | **BYOK。** 末尾数文字のみ表示 |
| D9 | 自分のアカウント設定 | `/settings/account` | メール・パスワード変更 |

**課金画面は作らない。** 請求は antpress の外で手動で行う（→ `DECISIONS.md` 3.10）。

**D3 のスコープ**: developer は `developer_id` で絞った自分のクライアントのみ。
`role = admin` だけが全件見られる（→ `DATA-MODEL.md` 1.1）。

**D8 が未設定の場合**: クライアントを AI プランに設定できない（D4 / D5 で弾く）。
生成が必ず失敗するため、設定時点で防ぐ。

### なぜ API キーと Webhook URL を developer 側に置くのか

| 項目 | 使う人 | 理由 |
| --- | --- | --- |
| 配信 API キー | **developer** | HP に埋め込むのは developer。クライアント（店舗オーナー）は一生触らない。見せると**誤って失効させて自分のサイトを壊すリスク**だけが増える |
| Webhook URL | **developer** | Vercel / Netlify の Deploy Hook URL。クライアントが理解も設定もできない値 |
| Anthropic キー | **developer** | 課金される当事者が developer |

**クライアントに見せない。** 権限ではなく画面自体を分けることで、事故の余地をなくす。

## 4. コンテンツ運用（`/client/*`）— client

| # | 画面 | パス | 内容 |
| --- | --- | --- | --- |
| C1 | ログイン | `/client/log_in` | |
| C2 | パスワードリセット | `/client/reset_password` | |
| C3 | **記事一覧** | `/client/articles` | 下書き / 公開 / 予約 でフィルタ。検索 |
| C4 | **記事編集** | `/client/articles/:id/edit`, `/client/articles/new` | **最重要画面。プランで UI が分岐**（→ 5 章） |
| C5 | カテゴリ一覧 | `/client/categories` | 作成・編集・並び替え・削除 |
| C6 | 画像管理 | `/client/images` | アップロード・一覧・削除・alt 設定 |
| C7 | **問い合わせ一覧** | `/client/inquiries` | 受信一覧。未読 / 既読 |
| C8 | **問い合わせ詳細** | `/client/inquiries/:id` | 内容表示。開いた時点で既読化 |
| C9 | フォーム設定 | `/client/settings/contact_form` | 5 項目を `非表示 / 任意 / 必須` で設定 |
| C10 | スタッフ管理 | `/client/settings/staff` | **オーナーのみ。** スタッフの発行・停止 |
| C11 | 自分のアカウント設定 | `/client/settings` | 表示テーマ・表示名・メールアドレスの確認 |
| C11b | パスワード変更 | `/client/settings/password` | ⚠️ **ここだけ再認証（sudo モード）が要る** |

**ログイン後の着地点は C3（記事一覧）** とする。ダッシュボードは作らない
（表示する指標がなく、1 画面増えるだけになる）。

## 5. 記事編集画面（C4）— プランによる分岐

同一のルートで、`clients.plan` によって編集領域を切り替える。

### 4.1 基本プラン

```
┌─────────────────────────────────────────┐
│ タイトル [_______________________]      │
│ スラッグ [_______________________]      │
├─────────────────────────────────────────┤
│ 本文        [ Markdown | WYSIWYG ]  ←切替 │
│ ┌─────────────────────────────────────┐ │
│ │  Toast UI Editor                    │ │
│ │  (phx-update="ignore")              │ │
│ └─────────────────────────────────────┘ │
├─────────────────────────────────────────┤
│ カテゴリ [▼ お知らせ]                    │
│ サムネイル [画像を選択]  ← C6 をモーダルで  │
│ 公開状態 ( )下書き (•)公開               │
│ 公開日時 [2026-09-03 10:00]  ←未来なら予約 │
├─────────────────────────────────────────┤
│              [ 保存 ]                    │
└─────────────────────────────────────────┘
```

### 4.2 AI プラン

```
┌─────────────────────────────────────────┐
│ タイトル [_______________________]      │
│ スラッグ [_______________________]      │
├─────────────────────────────────────────┤
│ 原文                                     │
│ ┌─────────────────────────────────────┐ │
│ │ (プレーンな textarea。体裁は問わない)  │ │
│ └─────────────────────────────────────┘ │
│           [ 生成・解析 ]                  │
├─────────────────────────────────────────┤
│ 生成結果          ● 生成中... ▓▓▓░░░      │
│ ┌─────────────────────────────────────┐ │
│ │ (ストリーミングで流れてくる)           │ │
│ │  自前実装。Toast UI は使わない          │ │
│ └─────────────────────────────────────┘ │
├─────────────────────────────────────────┤
│ カテゴリ / サムネイル / 公開状態 / 公開日時 │
│              [ 保存 ]                    │
└─────────────────────────────────────────┘
```

**生成中の挙動**

- `blog_articles.generation_status = generating` を立てて非同期実行
- LiveView にストリーミングで流し込む
- **ブラウザを閉じても生成は継続**し、再訪時に「生成中」または結果を表示する
- 再生成すると**上書き**（履歴は残さない → `DECISIONS.md` 3.1）

## 6. 権限（クライアント側）

| 画面 | オーナー | スタッフ |
| --- | --- | --- |
| C3 記事一覧 / C4 記事編集 | ✅ | ✅ |
| C5 カテゴリ | ✅ | ✅ |
| C6 画像 | ✅ | ✅ |
| C7 / C8 問い合わせ | ✅ | ✅ |
| C9 フォーム設定 | ✅ | **❌** |
| C10 スタッフ管理 | ✅ | ❌ |
| C11 自分のアカウント | ✅ | ✅ |

**方針**: スタッフは**コンテンツ運用**を担い、**設定変更は行わない。**
フォーム設定は HP の表示に直結し、必須項目を切り替えると問い合わせが取れなくなる
可能性があるため、オーナーに限定する。

| 区分 | 画面数 |
